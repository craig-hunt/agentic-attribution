## The demo's thesis

Payment is solved by x402. **Attribution is not.** When an agent uses a platform's catalog to decide, then pays the merchant directly, no cookie, referrer, or click exists to carry commission attribution.

This demo implements one answer: **Ed25519-signed attribution assertions that travel with the payment and drive automatic commission split at settlement.**

Three-layer protocol stack framing (AP2 authorization / ACP checkout / x402 settlement) is the sophisticated point. They stack; they do not compete.

`go build ./...` clean, `go vet` clean, `gofmt` clean, `tsc --noEmit` clean under strict. Go tests pass, 8 types tests pass, 13 merchant tests pass.

**Cross-language signing agreement is now proven rather than assumed.** Go's `json.Marshal` HTML-escapes `<`, `>`, and `&`; `JSON.stringify` does not. An identifier carrying any of the three would sign in Go and fail verification in TypeScript with nothing in either stack trace explaining why. `canonicalize` now uses an encoder with `SetEscapeHTML(false)`, two Go tests pin the exact bytes, and `cmd/fixture` mints a fixture whose publisher and product IDs deliberately contain `<` and `&` for the TypeScript suite to verify.

**Critical invariant already in place:** Go and TypeScript canonicalize signing input through a **fixed-field-order struct** so the bytes are identical across languages. If those drift, cross-language signature verification breaks. Unit tests cannot catch it; the Cypress suite is designed to.

## Settlement decisions worth defending in the room

These came out of building the state machine and are the kind of thing Round 3 will probe.

**Ordering.** Verify the assertion, validate the listing, ask the facilitator to verify, *then* claim, then settle, then confirm. The facilitator check precedes the claim so a malformed payload costs a round trip rather than burning a single-use assertion. Verify moves no value, so losing the claim race afterwards costs the caller nothing.

**Replay defense lives in the database.** The claim is an `INSERT ... ON CONFLICT DO NOTHING` against a primary key, not a `SELECT` followed by an `INSERT`. Two concurrent settlements of one assertion resolve in Postgres rather than racing in application code.

**Claim and pending row commit together.** A crash between them would otherwise burn an assertion with nothing on record to account for it.

**Rate reconciliation.** Search mints the assertion with the best rate across every offer on the product, so the merchant the agent picked may publish less. Settlement takes the lower of the signed rate and the merchant's current listing rate: the signature caps what the publisher can claim, and the listing caps what the merchant can be charged.

**A failed settlement keeps the assertion consumed.** Releasing the claim would let a caller grind one assertion against a flaky facilitator until a retry landed. Recovery issues a fresh assertion.

**No retry on `/settle`.** A timeout leaves the on-chain outcome unknown, and resending an EIP-3009 authorization that already landed risks a second transfer. Recovery belongs to a reconciler reading chain state, not to the request path.

**Truncation favors the publisher.** The split floors the platform fee and hands the remainder to the publisher, so the three amounts always sum exactly and the ledger's `commission_splits_exactly` CHECK can never fail at write time.

## Technical decisions already locked

- Ed25519, not JWT. Rejected JWT on size (64-byte sigs matter inside a payment envelope) and on algorithm-confusion history
- Commission rate signed inside the assertion so neither side can alter it
- Integer truncation on the split; **publisher absorbs the remainder** so the ledger CHECK constraint always holds
- Assertion binds to `search_request_id`, creating the audit chain query → payment → ledger
- Base Sepolia testnet, real EIP-3009, facilitator sponsors gas
- Commission split is a Postgres ledger entry, **not** a second on-chain transfer (models real payout cycles)
- Merchant is simulated; ADR-0005 states the boundary and includes the criticism a skeptic would raise
- **On-chain finality has no chargeback path.** Documented as a real tension needing an escrow layer, not hidden
